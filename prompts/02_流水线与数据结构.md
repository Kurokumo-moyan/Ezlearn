# 流水线、各阶段 Prompt 与数据结构

> 把 MATH5855 学习站的实际工作顺序拆成软件可以自动执行的阶段。每个阶段有明确的输入、输出和专用 prompt；所有阶段都共享 `01_主Prompt_课程讲解生成器.md` 作为系统提示前缀。

## 目录

1. 总体架构
2. 各阶段 Prompt（S1–S8）
3. 数据结构（课程、资料、证据、章节、内容块、练习、交互组件）
4. 渲染层要求（从 MATH5855 学习站继承的界面规范）
5. 质量校验清单（自动 + 人工）
6. 已知坑与对策

---

## 1. 总体架构

```
 资料上传 ─► S1 资料解析 ─► S2 证据抽取 ─► S3 学科判定 ─► S4 考核与真题分析
                                                            │
                                         用户确认 ◄─ S5 课程方案（目录、权重、交互清单）
                                                            │
                         ┌──────────── 逐章循环 ────────────┤
                         ▼                                  │
                   S6 章节生成 ─► S7 校验（执行代码 / 对照原文 / 渲染检查）─► 渲染
                                                            │
                   新资料到达 ─► S8 增量更新（只改受影响章节）
```

关键设计决定（来自实际经验）：

| 决定 | 原因 |
|---|---|
| 先出"课程方案"并让用户确认，再批量生成 | 一门课 15–20 章，方向错了返工代价极高；交互组件选择需要用户认可 |
| 证据抽取单独一个阶段 | "不考 / 重点"标记必须可追溯到原话；混在生成阶段里容易编造 |
| 逐章生成而不是一次生成全书 | 上下文有限；每章需要读该章原文 + 习题答案 + 相关转录，单独处理质量高 |
| 校验阶段必须能执行代码 | 数值例子、SQL 查询、统计结果手算极易出错 |
| 增量更新 | 课程进行中资料不断增加（新转录、批注版 slides、新 lab），重做全书不现实 |
| 内容存成结构化块，渲染交给前端 | 同一内容可以换主题、换语言显示、导出、搜索，组件可以按学科替换 |

## 2. 各阶段 Prompt

以下每个 prompt 都接在主 Prompt 之后使用。`{{…}}` 为软件注入的变量。

### S1 资料解析（Ingest）

**输入**：用户上传的文件列表（PDF、PPTX、DOCX、图片、音频 / 视频转写、代码、数据集、网页链接）。
**工具**：文本提取（pdftotext / pypdf）、版面分析、OCR、页面渲染为图片 + 视觉模型读取（处理手写批注）、音视频转写。

```
对每个文件判断它的角色，并提取可用文本：
- 角色：course_outline / slides / annotated_slides / textbook / lecture_notes / transcript /
  tutorial / tutorial_solution / lab / lab_solution / past_exam / past_exam_solution /
  assignment(当期) / dataset / code / reading / other
- 保留原始结构：章节号、小节标题、页码、幻灯片编号、题号。
- 图片型或手写页：渲染成图片后用视觉读取，不要只依赖 OCR；手写内容转写为文字并标注
  "来自手写批注，第 N 页"。
- 转录：保留日期，按段落切分；没有时间戳时记录段落序号。
- 当期作业 / 项目：只记录要求和截止日期，标记 no_solutions=true。
输出 Material 列表（结构见第 3 节）。不要总结，不要改写原文。
```

### S2 证据抽取（Evidence）

```
在所有 transcript / annotated_slides / course_outline / slides 中查找与考核相关的明确表述，
逐条输出 Evidence：
- 类型：not_examinable / emphasised / exam_format / exam_hint / assessment_rule / correction
  （老师纠正口误或讲义错误）/ scope（"本周讲到哪里"）
- 必须包含：来源文件、位置（日期 + 段落 / 页码）、原文引用（≤ 40 词）、指向的知识点。
- 检索建议：先用关键词定位（examinable, not assess, skip, important, focus, exam, final,
  midterm, assignment, won't, 必考, 不考, 重点），再读前后各约 300 字确认指代对象。
- 指代不明时标 confidence=low 并说明推定理由（例如"按顺序推定指性质 4"）。
- 没有证据就不输出，不要推测。
另外输出 coverage：哪些周 / 章节有转录或批注，哪些没有。
```

### S3 学科判定（Profile）

```
根据课程资料判断本课的学科类型（可多选，按章节给出比例），从学科档案库中选择
最匹配的一个或多个档案（见 03_学科适配档案.md），说明判断依据：
- 考试题型（推导、计算、读软件输出、写代码、病例分析、案例论述、选择题……）
- 资料形态（公式密度、代码量、图片 / 图表量、案例量）
- 学习者最可能卡住的地方
输出：primary_profile、secondary_profiles、每章适用的档案、推荐的内容块与交互组件。
```

### S4 考核与真题分析（Exam analysis）

```
1. 从大纲提取考核结构：各项占比、形式、时长、是否开卷 / 机考、门槛（hurdle）。
2. 把每道往年真题映射到章节：题号、分值、题型、考查的知识点、对应教材小节。
3. 汇总每章分值；识别固定题型套路（例如"构造检验统计量 + 分布 + 拒绝域"）。
4. 结合 S2 证据判断"是否存在重点"，逐条给出依据；推断必须标明。
5. 若往年试卷与本学期教师 / 形式不同，指出差异对参考价值的影响。
6. 给出复习优先级表（最高 / 高 / 中 / 低 / 不考）与理由。
输出 ExamAnalysis（第 3 节）。没有往年真题时，改用大纲学习目标 + 题型说明 + 证据，并整体标为推断。
```

### S5 课程方案（Plan，需用户确认）

```
基于 S1–S4 产出课程方案，交给用户确认：
- 目录依据（教材章节 / 讲义编号 / slides 编号）及理由
- 每章：标题（双语）、来源、对应周次、权重估计、需要的内容块侧重、交互组件清单
  （每个组件写清：解决什么理解难点、交互方式、默认数据来源）
- 需要用户确认的问题（例如考试是否允许计算器、某主题今年是否讲授、本机是否有 R）
- 不做什么（例如不提供当期项目代码）
方案要具体到可以直接开工；交互组件只选真正有帮助的。
```

### S6 章节生成（Write chapter）

```
现在生成第 {{CHAPTER_ID}} 章。你可以使用的资料：
- 本章原文：{{CHAPTER_SOURCE_TEXT}}
- 本章习题与官方解答：{{EXERCISES_AND_SOLUTIONS}}
- 与本章相关的证据：{{EVIDENCE_FOR_CHAPTER}}
- 与本章相关的真题：{{EXAM_QUESTIONS_FOR_CHAPTER}}
- 本章交互组件计划：{{WIDGET_PLAN}}
- 学科档案：{{DISCIPLINE_PROFILE}}
按主 Prompt 第三节的固定结构输出 Chapter（内容块数组）。要求：
- 小节编号与原文一致；每个公式 / 规则 / 代码有组成部分说明；
- 难点附具体例子（example 块），例子中的每个数字都给出计算过程，并在 verify 字段
  中写出用于核算的代码；
- 证据块必须引用 Evidence 的 id；
- 习题每个小题单独 solution；
- 不确定的地方写 todo，不要编造。
```

### S7 校验（Verify）

自动执行，不依赖模型自觉：

| 校验 | 方法 | 不通过时 |
|---|---|---|
| 数值正确 | 执行每个 `example.verify` / `exercise.solution.verify` 代码，对比文中数字 | 回到 S6 修正该块 |
| 代码 / 查询可运行 | 在沙箱运行 `code` 块（SQL 在样例数据库，R / Python 在对应环境） | 修正或标"未验证" |
| 证据可追溯 | 每个 key / exam / skip 块的 evidence id 存在且引用原文能在资料中找到 | 删除标记或降级为推断 |
| 与原文一致 | 抽查定义、定理、公式与原文逐字比对（LLM 判别 + 字符串比对） | 修正 |
| 结构完整 | 每章有速查表；每个 exercise part 有 solution；术语有双语 | 补全 |
| 渲染 | 公式渲染零错误；移动端无横向滚动；深色模式可读；组件可初始化 | 修正 |
| 诚信 | 内容不含当期作业答案（与 assignment 材料做相似度比对） | 删除 |

模型辅助校验 prompt：

```
你是审稿人。逐块检查下列章节内容是否：(1) 与原文一致；(2) 数字与 verify 执行结果一致；
(3) 标记有证据；(4) 对零基础学习者可理解（指出跳步、未定义的符号、未解释的术语）。
只报告问题，每条给出块 id、问题、建议修改。不要重写全文。
```

### S8 增量更新（Update）

```
新增资料：{{NEW_MATERIALS}}
1. 先运行 S1、S2，只针对新资料。
2. 找出受影响的章节与首页部分（新证据、新例子、新题目、范围变化、纠错）。
3. 输出变更清单（章节、块、变化类型、证据），用户确认后只修改这些块。
4. 更新首页的证据覆盖说明（例如"转录覆盖 Week 1–8"）。
不要重写未受影响的内容。
```

## 3. 数据结构

以 JSON 表示，字段可按实现语言调整。

```jsonc
// 资料
Material {
  id, filename, role,                // 见 S1 角色列表
  week?, date?, no_solutions: bool,  // 当期作业为 true
  pages: [{ n, text, image_ref?, handwritten_text? }]
}

// 证据
Evidence {
  id, type,                          // not_examinable | emphasised | exam_format | exam_hint | assessment_rule | correction | scope
  material_id, location,             // "2026-09-23 第 14 段" / "p.12"
  quote,                             // 原文 ≤ 40 词
  target,                            // 指向的知识点 / 小节 id
  boundary?,                         // "只排除证明"
  confidence: "high" | "low", note?
}

// 课程
Course {
  code, title, teaching_language, exam_language,
  profiles: [profile_id],
  assessment: [{ name, weight, format, timing, hurdle? }],
  exam_analysis: ExamAnalysis,
  chapters: [Chapter], tutorials: [TutorialSet], quick_refs
}

ExamAnalysis {
  papers: [{ year, duration, total_marks, questions: [{ no, marks, type, chapters, topics, solution_ref }] }],
  marks_by_chapter: { chapter_id: number },
  key_topic_judgement: [{ claim, evidence_ids, is_inference }],
  priority: [{ level, chapters, reason }]
}

// 章节
Chapter {
  id, number, title, title_exam_lang, group, weight: 0..3,
  sources: [{ material_id, pages }], week, lecture_dates,
  blocks: [Block]
}

// 内容块（核心）
Block =
  | { type: "heading", level: 2|3, id, number, text, text_exam_lang, badges? }
  | { type: "paragraph", rich_text }                    // 支持 {term}、$math$、**强调**
  | { type: "formula", latex, display: true, symbols: [{ symbol, meaning }] }
  | { type: "example", title, body: [Block], verify?: { lang, code, expected } }
  | { type: "box", kind, title?, body: [Block], evidence_ids?, is_inference? }
      // kind: key | exam | skip | definition | result | pitfall | intuition | template | extension
  | { type: "table", header, rows }
  | { type: "code", lang, source, runnable: bool, annotations?: [{ line, note }], expected_output? }
  | { type: "figure", src, caption, source_ref, license? }
  | { type: "widget", widget, config, fallback_text }
  | { type: "exercise", id, title, source, stem: [Block],
        parts: [{ label, question: [Block], solution: [Block], verify? }] }
  | { type: "quick_ref", rows: [{ concept, content }] }

// 术语（全局，供双语切换、术语表、搜索）
Term { id, teaching_lang, exam_lang, aliases?, first_chapter, definition_block_ref }
```

## 4. 渲染层要求（继承 MATH5855 学习站，已验证好用）

- **布局**：左侧固定目录（课程章节 → 当前章展开小节，滚动高亮）；正文单栏最大约 880px；移动端目录变抽屉。
- **主题**：白天 / 黑夜 / 跟随系统；全部颜色用语义 token（重点 = 金、真题 = 红、不考 = 灰虚线、定义 = 蓝、结论 / 练习 = 绿、易错 = 紫）。
- **双语开关**：一键隐藏 / 显示考试语言术语。
- **折叠**：具体例子、每个小题的解答默认折叠；章首"展开 / 收起全部解答"。
- **搜索**：中英文全文，结果定位到小节。
- **进度**：每章"已掌握"标记，只存本地，不做测验。
- **侧栏权重**：●●● 表示期末权重估计。
- **公式**：KaTeX；长公式独占一行居中，超宽时横向滚动，避免两个长公式挤在同一行。
- **交互组件**：统一的组件注册机制（`type` → 渲染函数），组件只用主题 token 取色，宽度自适应。
- MATH5855 的静态实现（HTML + JS，无构建）可作为前端原型：见 `课程学习站模板/engine/` 或 skill `course-study-site`。

## 5. 质量校验清单

自动（每次生成后）：
1. 数值 / 代码 / 查询执行核对全部通过
2. 每个 key / exam / skip 有有效证据
3. 公式渲染零错误；移动端宽度无溢出；深色模式可读
4. 每个练习小题都有独立解答
5. 当期作业相似度检查通过

人工（学习者或审核者抽查）：
1. 零基础能否读懂第一节（是否有跳步、未定义的符号）
2. 例子是否真的帮助理解，而不是重复公式
3. 交互组件是否值得存在
4. 真题解答是否能拿满分

## 6. 已知坑与对策

| 坑 | 对策 |
|---|---|
| 手写批注 OCR 读不出 | 页面渲染成图片，用视觉模型读 |
| 转录无时间戳、口误多 | 关键词定位 + 上下文确认；口误与正确说法都记录并注明 |
| 讲义本身有错（自由度写错、展开漏项、定义写错） | 在原位置用"资料勘误"框注明 |
| "不考"范围被扩大解读 | Evidence 必须写 boundary；只排除证明时结论仍保留"要会用" |
| 往年试卷换了老师 / 形式 | 首页说明差异，降低其权重判断的置信度 |
| 数值例子手算出错 | 强制 verify 代码执行 |
| 长公式在手机上溢出 | 一行一个长公式；表格横向滚动 |
| 生成内容泄露当期作业答案 | assignment 材料标 no_solutions，生成与校验双重过滤 |
| 一次性生成全书质量下降 | 逐章生成，每章只喂相关材料 |
