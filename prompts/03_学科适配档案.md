# 学科适配档案（Discipline Profiles）

> 主 Prompt 是学科无关的；本文件给出各学科的"适配档案"，在 S3 学科判定后注入到 `{{DISCIPLINE_PROFILE}}`。一门课可以同时使用多个档案（按章节切换）。
> 每个档案的结构相同：**识别信号 → 学习者最常卡在哪里 → 内容块侧重 → 推荐交互组件 → 具体例子怎么写 → 校验方式 → 学科特有风险**。
> 前三个档案来自已有实践（MATH5855 多元统计、COMP6714 信息检索、DATA5002 数据可视化）；其余是按同一方法论推演的设计，开发时建议用一门真实课程先验证。

## 1. 数学 / 统计理论

- **识别信号**：定理、证明、推导；考试要求 "show that / derive / prove / find the distribution"。
- **卡点**：不知道每个符号代表什么；不知道公式怎么代数字；证明跳步。
- **内容块侧重**：`formula` + `symbols` 是主角；每个首次出现且符号多的公式配 `example`（2×2 矩阵、3 个观测这类小数字）；`box.template` 给出推导题的得分步骤；证明里被老师排除的部分用 `box.skip` 并写边界。
- **交互组件**：参数滑块（分布形状、置信区域、临界值随 n 变化）；可拖动的几何图（投影、椭圆、主成分方向）；统计量计算器；由特征值算多个检验统计量这类"一输多出"计算器。
- **具体例子写法**：先给数据 → 逐步代入 → 给中间矩阵 / 数值 → 一句话解释意义（例如"条件方差缩小比例 = ρ²"）。
- **校验**：所有数值用 Python / R 重算；分布分位数用软件查。
- **风险**：讲义符号与通用教材不同（以讲义为准）；自由度、分母 n 与 n−1 的混淆。

## 2. 算法 / 计算机理论

- **识别信号**：伪代码、复杂度、"给数据按算法算出结果"、"修改算法支持…"。
- **卡点**：算法运行时状态太多记不住；不会改算法。
- **内容块侧重**：伪代码 `code`（不可运行，带逐行注释）+ 复杂度 `box.result` + "如何修改"`box.template`。
- **交互组件**：**逐步演示（stepper）**——每一步显示数据结构状态和一句说明（列表合并、索引构建、动态规划表、图遍历、迭代算法如 PageRank / K-means）；编码 / 解码器（变长编码、哈希）；可编辑输入，默认填往年真题数据。
- **具体例子写法**：小规模输入 + 完整手算轨迹表。
- **校验**：用参考实现跑出每一步状态，与文中逐步对照。
- **风险**：边界条件（空列表、相等元素）；复杂度与输入假设。

## 3. 编程 / 数据可视化

- **识别信号**：考试给代码要求阅读 / 修改 / 补全；作业交代码和图。
- **卡点**：预测不了代码输出；不知道改哪个参数。
- **内容块侧重**：`code` + 逐行 `annotations`（作用、改了会怎样）+ 真实输出图；"改代码练习"：原代码 + 要求 + 目标输出，答案用 diff 显示改动行。
- **交互组件**：前后对比切换（同一代码改一个参数）；语法拼装台（选映射 / 图形类型 → 同时生成代码与图）；可选浏览器内运行环境（webR、Pyodide）；设计原则的"好图 / 坏图"切换（配色与色盲模拟、坐标轴基线、过度绘制）。
- **具体例子写法**："最小可运行示例"：小数据 + 完整代码 + 输出。
- **校验**：所有代码在真实环境运行，输出图由真实工具生成（不手画模拟）。
- **风险**：版本差异（函数改名、参数废弃）；不得给当期作业代码。

## 4. 数据库与 SQL

- **识别信号**：关系模型、ER 图、SQL 查询、范式、事务、索引；考试写查询 / 画 ER / 判断范式。
- **卡点**：SQL 书写顺序与执行顺序不同；JOIN 结果行数想不清；GROUP BY / HAVING 的作用对象；NULL 的三值逻辑；范式分解步骤。
- **内容块侧重**：
  - 每个查询：`code(lang=sql, runnable=true)` + 逐子句说明 + **结果表**（真实执行结果）；
  - 概念对比 `table`：WHERE vs HAVING、INNER vs LEFT JOIN、DELETE vs TRUNCATE、各隔离级别能防止的异常；
  - 范式、函数依赖、闭包计算用 `example` 逐步推；
  - 关系代数与 SQL 对照表。
- **交互组件**：
  - **浏览器内 SQL 沙箱**（sql.js / DuckDB-WASM）：预载课程样例数据库，学习者可改查询立即看结果；
  - **执行顺序动画**：FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT，每步显示中间表；
  - **JOIN 行匹配动画**：两张小表逐行匹配，LEFT JOIN 补 NULL 高亮；
  - ER 图 → 关系模式转换演示；函数依赖闭包 / 候选键计算器；范式分解 stepper；
  - 事务时间线：两个事务交错执行，展示脏读 / 不可重复读 / 幻读，切换隔离级别看哪些被阻止；
  - B+ 树插入 / 分裂 stepper；查询计划树展示。
- **具体例子写法**：3–6 行的小表 + 查询 + 每一步中间结果 + 最终结果。
- **校验**：每条 SQL 在指定方言（MySQL / PostgreSQL / SQLite / Oracle，按课程）中真实执行，结果表直接取执行输出；方言差异处注明。
- **风险**：方言差异（LIMIT vs TOP vs FETCH）；NULL 比较；课程要求的范式定义版本。

## 5. 经济学

- **识别信号**：供需、弹性、均衡、博弈、宏观模型（IS-LM、AD-AS、Solow）、计量；考试画图分析、求均衡、解释政策效果。
- **卡点**：曲线移动 vs 沿曲线移动；比较静态的方向；模型假设记不清；图和式子对不上。
- **内容块侧重**：
  - 每个模型：假设列表 → 方程（`formula` + 变量含义与单位）→ 图 → 结论；
  - **"冲击分析模板"**（`box.template`）：哪条曲线、向哪移、新均衡、价格 / 数量 / 福利变化、长期调整；
  - 政策效果、不同学派观点用对比 `table`；
  - 计量部分沿用"统计档案"与"读软件输出"写法。
- **交互组件**：
  - **可拖动 / 滑块控制的曲线图**：供需、成本曲线、IS-LM、AD-AS；滑动外生变量看曲线移动和新均衡，同时显示消费者 / 生产者剩余、无谓损失面积；
  - 弹性、乘数、税负归宿计算器；
  - 博弈支付矩阵：自动高亮最优反应、标出纳什均衡；扩展式博弈逆向归纳 stepper；
  - 动态模型的时间路径图（Solow 收敛、蛛网模型）。
- **具体例子写法**：给具体需求 / 供给函数 → 求均衡 → 加税后重新求 → 计算剩余变化；每个数字可核算。
- **校验**：均衡解与面积用代码求解；图与数值一致；曲线移动方向与文字一致。
- **风险**：符号约定（价格在纵轴）；短期 / 长期混淆；把规范判断写成实证结论；不同教材对同一模型的形式不同（以课程为准）。

## 6. 医学 / 健康科学

- **识别信号**：解剖、生理、病理、药理、临床技能；考试为 MCQ / 简答 / 病例分析 / OSCE。
- **卡点**：信息量巨大且分散；机制链条长；相似疾病 / 药物易混；临床推理顺序。
- **内容块侧重**：
  - **机制链**：病因 → 病理生理 → 症状体征 → 检查发现 → 治疗靶点，用流程图或分步列表；
  - **对比表**（主力）：鉴别诊断、同类药物（机制、适应证、不良反应、禁忌、相互作用）、各型分类标准；
  - **病例**：分步揭示的病例题（主诉 → 病史 → 查体 → 检查 → 诊断 → 处理），每步先让学习者想再展开；
  - 术语三语：教学语言 + 英文 + 拉丁 / 词根拆解（词根词缀帮助记忆）；
  - 正常值 / 参考范围表，标明单位体系（SI / 常规单位）。
- **交互组件**：
  - **可悬停标注的解剖 / 组织学图**（必须来自课程资料或有授权的图库，注明来源与许可）；
  - 机制流程图：点击节点展开解释，标出药物作用点；
  - 临床计算器：BMI、阴离子间隙、校正钙、eGFR、Glasgow 评分、Wells 评分等（公式与版本以课程为准）；
  - 分步病例模拟（OSCE 风格）；生理曲线滑块（例如 Frank-Starling、氧解离曲线随 pH / 温度移动）。
- **具体例子写法**：一个具体病人的数值（如血气结果）→ 逐步判读 → 结论。
- **校验**：所有剂量、参考值、诊断标准逐条对照课程资料（及其引用的指南版本）；计算器公式与课程一致并注明版本。
- **学科特有风险（重要）**：
  - 明确声明内容仅用于课程学习，**不构成医疗建议**；不对个人健康问题给建议；
  - 剂量、指南随版本变化：注明来源与年份，冲突时以课程资料为准并提示；
  - 图片版权与患者隐私（病例去标识化）；
  - 不编造任何药物数据或统计数字——资料里没有就写"资料未给出"。

## 7. 法学

- **识别信号**：判例、法条、案例分析题（IRAC）、论述题。
- **卡点**：规则要件拆不清；判例事实与规则混在一起；答题结构。
- **内容块侧重**：法条要件拆解表；判例卡片（事实、争点、判决、理由、意义）；IRAC 答题模板；相似规则对比。
- **交互组件**：要件检查清单（勾选事实是否满足各要件）；判例时间线与法条演变；论证图（主张—理由—反驳）。
- **校验**：法条原文与课程资料逐字核对；注明法域与时点。
- **风险**：法域差异；不构成法律意见。

## 8. 人文社科（历史、哲学、社会学、政治学）

- **识别信号**：论述题、文本细读、理论比较、史料分析。
- **卡点**：理论之间的关系；论证结构；时间线与因果。
- **内容块侧重**：概念 / 理论对比表；原著关键段落 + 逐句解读；论证结构拆解；论文 / 论述题答题框架。
- **交互组件**：可缩放时间线；人物 / 学派关系网络图；论证图；地图（历史地理）。
- **校验**：引文与原文核对，标注页码。
- **风险**：观点与事实区分；避免把一家之言写成定论。

## 9. 自然科学实验类（物理、化学、生物）

- **识别信号**：定律推导 + 计算 + 实验设计 / 数据处理。
- **内容块侧重**：物理量单位与量纲检查；实验步骤、误差来源；计算题模板。
- **交互组件**：参数模拟（运动、电路、反应速率、种群动态）；单位换算 / 量纲检查器；分子 / 结构 3D 查看（来源需授权）。
- **校验**：数值与单位用代码核算；实验数据处理可复现。
- **风险**：单位制混用；实验安全说明以课程为准。

## 10. 工程 / 量化应用（金融、运筹、控制、计量）

- **识别信号**：模型 + 数值求解 + 软件输出解读。
- **内容块侧重**：模型建立模板；"读输出"逐项解释表；敏感性分析。
- **交互组件**：参数敏感性滑块（NPV、期权价格、线性规划可行域与目标函数平移、控制系统阶跃响应）；求解过程 stepper（单纯形法表）。
- **校验**：所有结果用求解器 / 代码核对。
- **风险**：模型假设被忽略；金融内容不构成投资建议。

## 11. 语言学习

- **识别信号**：词汇、语法、听说读写技能考核。
- **内容块侧重**：语法规则 + 例句 + 常见错误；词汇按主题与词根组织。
- **交互组件**：例句变形（时态 / 语态切换）；发音（需音频来源）；间隔重复卡片（只作为可选自测，不强制）。
- **风险**：方言 / 地区差异；音频版权。

## 12. 新增学科档案的模板

```markdown
## N. 学科名
- 识别信号：资料形态 + 考试题型
- 卡点：学习者最可能在哪里卡住（3–5 条）
- 内容块侧重：哪些块是主角，哪些模板框要固定提供
- 交互组件：每个组件写"解决哪个卡点 + 交互方式 + 默认数据"
- 具体例子写法：最小可行例子的形态
- 校验：如何自动核对正确性（执行、对照原文、对照标准）
- 风险：学科特有的错误类型、版权、伦理、免责声明
```

判断一个交互组件值不值得做的三个问题：
1. 静态文字 + 一张图能否讲清？能就不做。
2. 学习者"动一下"之后是否立刻看到原本想不到的变化？
3. 默认状态是否已经是课程里的真实例子或真题数据？
