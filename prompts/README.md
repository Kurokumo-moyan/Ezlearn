# 通用学习软件 · Prompt 与设计规格

从 MATH5855 学习站（以及为 COMP6714、DATA5002 做的方案）中提炼出的、不依赖具体学科的核心逻辑，用于开发一个能处理任意课程（数据库 SQL、经济学、医学……）的学习软件。

| 文件 | 内容 | 给谁用 |
|---|---|---|
| `01_主Prompt_课程讲解生成器.md` | 学科无关的核心系统提示：目标、12 条原则、每章固定结构、内容块类型、证据标记规则、输出前自检 | 软件中所有生成阶段共享的系统提示前缀 |
| `02_流水线与数据结构.md` | 8 个阶段（解析 → 证据 → 学科判定 → 真题分析 → 课程方案 → 逐章生成 → 校验 → 增量更新）各自的 prompt；数据结构（资料、证据、章节、内容块、练习）；渲染要求；校验清单；已知坑 | 后端编排与前端开发 |
| `03_学科适配档案.md` | 11 个学科档案（数学统计、算法、编程可视化、数据库 SQL、经济学、医学、法学、人文社科、自然科学、工程量化、语言）+ 新增档案模板 | 学科判定后注入主 Prompt；决定内容侧重与交互组件 |

相关的已有实现：
- `课程学习站模板/`：静态网页引擎（HTML + JS，无构建）、设计规范 `DESIGN.md`，可作为前端原型。
- `course-study-site.skill`：同一套逻辑的 agent skill 版本，适合在 Claude 等 agent 中直接使用。

## 一、产品要解决的问题

学生手里有一门课的全部资料（slides、讲义、录音转写、tutorial、往年真题），但：
- 资料多而散，零基础不知道从哪里开始，原有笔记"太简略，不知道在讲什么"；
- 不知道考试真正考什么、哪些可以略过；
- 公式、代码、机制看得懂字面，不会用；
- 教学语言和考试语言可能不同。

软件把这些资料变成一本**按课程自己的结构组织、零基础可读、每个结论都能追溯到来源、带交互演示**的学习书，并随课程进度增量更新。

## 二、从实际需求中提炼的产品原则

这些原则来自一位学生在真实使用中逐步提出的要求，按提出顺序排列，是产品设计的验收标准：

| # | 学习者原话的意思 | 产品原则 |
|---|---|---|
| 1 | 笔记太简略，不知道在讲什么；公式里每个字母是什么意思 | 从直觉讲起；每个公式 / 代码 / 规则解释组成部分 |
| 2 | 中文教学，考试用英文 | 教学语言讲解 + 考试语言术语，可切换 |
| 3 | 左边按讲义目录，点了能跳转；白天 / 黑夜主题 | 目录跟随课程原有结构；阅读体验优先 |
| 4 | 分析往年题目和分数构成，判断有没有重点 | 真题 → 章节 → 分值映射；结论附依据 |
| 5 | 老师说可以略过的证明 / 知识点要标出来 | 证据驱动的"不考"标记，附原话与边界 |
| 6 | 例题按书上的解法，精简但能拿分 | 解答跟随官方思路，写到得分为止 |
| 7 | 不要反复提问确认我是否掌握 | 不做强制测验；自测答案折叠，学习者自主 |
| 8 | 把 TUT 题目也加进来 | 所有练习来源统一收录到对应章节 |
| 9 | 难懂的公式下面加可展开的数值例子；长公式居中、短公式随文；每个小题分别展开答案 | 折叠式具体例子；排版规则；逐小题折叠 |
| 10 | 更新了新的转录和批注 slides | 增量更新，只改受影响部分 |
| 11 | 根据不同课程加合适的交互图像、动画 | 学科档案驱动的交互组件，只在有帮助处使用 |
| 12 | 想推广到 SQL、经济学、医学等任意课程 | 学科无关的核心 + 可插拔的学科档案 |

## 三、架构建议（MVP → 完整版）

**MVP（单用户、本地）**
1. 上传资料文件夹 → S1 解析（PDF 文本 + 页面图片给视觉模型）。
2. S2–S5 生成证据库、真题分析和课程方案，用户在界面上确认 / 修改方案。
3. S6 逐章生成结构化内容块（JSON），S7 在沙箱中执行所有 verify 代码。
4. 前端用块渲染器显示（可直接改造 `课程学习站模板/engine/`）。

**完整版需要补的能力**
- 代码 / 查询沙箱：Python、R、SQL（sql.js / DuckDB-WASM 可在浏览器内）、必要时容器。
- 交互组件库：按学科档案逐步扩充（stepper、slider-plot、calc、SQL 沙箱、曲线拖动、解剖标注图、病例步进……），统一注册接口和主题 token。
- 证据浏览：点击任何"重点 / 不考"标记，可跳到原始资料对应位置。
- 增量更新：资料版本管理 + 变更清单审阅界面。
- 多语言 UI；导出（PDF / Markdown）；离线使用。
- 合规：当期作业识别与过滤；医学 / 法律 / 金融免责声明；图片版权记录。

**建议的开发顺序**：先用一门真实课程跑通 MVP（例如 SQL 课，它的"执行校验"最容易自动化），再用一门差异最大的课（例如医学）检验学科档案机制是否足够灵活。

## 四、怎么使用这些 prompt

- 在 LLM 调用中，系统提示 = `01` 的"系统提示"部分 + 对应学科档案（`03` 中选一个或多个章节）+ 当前阶段的 prompt（`02` 第 2 节）。
- `{{…}}` 变量由软件从前一阶段的输出中填入。
- 每个阶段的输出都按 `02` 第 3 节的数据结构返回 JSON，便于校验和渲染。
